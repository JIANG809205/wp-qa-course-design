# 第 4 章　测试用例设计

## 4.1 设计方法

按 ISO/IEC/IEEE 29119-4 的用例设计技术，针对不同模块选用不同方法：

| 方法 | 适用模块 | 示例 |
|---|---|---|
| 等价类划分 | 登录、表单字段、参数校验 | 密码分为"正确 / 错误 / 空 / 超长"四类 |
| 边界值分析 | 分页参数、文件大小、标题长度 | `per_page` = 1 / 100 / 101 / 0；标题 200 / 201 字符 |
| 状态迁移 | 文章状态、评论状态 | 草稿 → 待审 → 已发布 → 回收站 |
| 场景法 | 端到端业务流 | 投稿者撰写 → 编辑审核 → 前台可见 |
| 错误推测 | 安全与上传 | 伪装 php 文件、中文件名、0 字节文件 |
| 权限矩阵 | 角色权限 | 6 角色 × 6 操作 = 36 格 |

## 4.3 典型用例（节选）

**TC-PERM-001　投稿者不能发布**

| 项 | 内容 |
|---|---|

| 步骤 | 1) 进入新建文章；2) 点击"提交复审" |

| 判定 | 通过 |

**TC-MEDIA-003　伪装成图片的 php 文件**

| 项 | 内容 |
|---|---|
| 步骤 | 上传 `shell.php.jpg`（内容为 `<?php echo 'pwn'; ?>`） |

| 判定 | 通过（但错误码语义不准确，见 DEF-009 讨论） |

**TC-PERF-001　首页性能基准**

| 项 | 内容 |
|---|---|

| 预期 | P95 < 1000ms |
| 实际 | 静态首页 124.1 TPS / P95 523ms；列表页 226.0 TPS / P95 768ms |

## 5.3 自动化实现

**Selenium 栈（9 条）**：Page Object 模式，`pages/` 存页面对象、`tests/` 存用例，TestNG 组织，失败自动截图并附在 Allure 报告中。9/9 通过，耗时 25.96 秒。

**pytest 栈（26 条）**：用 requests 直调 REST 接口与页面，覆盖媒体、评论、状态迁移、设置、主题插件、安全等模块。用应用密码（Application Password）实现按角色鉴权，避免反复登录。

**为什么两套**：UI 用例验证"用户可见行为"，接口用例验证"权限与数据的最终边界"。二者互补——权限矩阵的双通道验证正是这一思路的延伸。

## 5.4 权限矩阵（双通道）

对 6 个角色（内置 5 个 + 自定义 auditor）× 6 个关键操作共 **36 格**，每格做两件事：
- **通道 A**：用该角色登录后台，访问页面，检查期望元素是否存在；
- **通道 B**：带 Cookie 与 REST nonce 直调接口，看返回码。

**结果：36 格全部符合预期，0 越权**；连跑 3 次，36 格结论完全一致（0 变化）。自定义角色 `auditor`（可审评论、不可发布/上传/建用户）的表现与设计一致，说明 WordPress 能力模型对自定义角色同样生效。

**过程中修正的两个测量错误**（方法学价值高于结论本身）：

| 问题 | 症状 | 根因 | 修正 |
|---|---|---|---|
| nonce 取错 | 所有接口一律 403，错误码 `rest_cookie_invalid_nonce` | 从后台 HTML 正则抓 nonce，抓到的是别的 nonce | 改调 `admin-ajax.php?action=rest-nonce` |
| 页面判据太粗 | 管理员访问"新建用户"被误判为拒绝 | 用"权限"关键词判断，正常页面也含该词 | 改为判"期望元素是否存在"（如 `#createuser`） |

若不查这两点，报告里会出现"4 处越权"的假缺陷。

## 5.5 兼容性测试

**Chrome 158** 与 **Firefox 155** 两种浏览器 × 3 种视口（1920×1080 / 1366×768 / 375×812）× 4 个页面（首页、博客列表、登录页、后台列表）= **24 组**。

判据：页面横向滚动宽度不得超出视口 4px；不得存在宽度超过视口的元素。

**结果：Chrome 12/12、Firefox 12/12，合计 24/24 通过，0 溢出**。375px 下 WordPress 后台在两种浏览器中均自动切换为移动布局（顶部折叠菜单），未出现横向滚动。

## 5.6 测试数据管理

测试会真实写入数据，必须清理，否则会污染后续测试与截图：

| 污染类型 | 来源 | 清理方式 |
|---|---|---|
| 测试文章（`perm-*`） | 权限矩阵验证"能否发布" | `cleanup.php` 按标题前缀删除 |
| 被改标题的文章 | 权限矩阵验证"能否编辑他人文章" | 按正文编号还原标题与 slug |
| 测试用户 | 权限矩阵验证"能否建用户" | 按登录名前缀删除，内容转交 admin |
| 测试评论 | pytest 评论用例 | 按内容前缀删除 |
| 站点标题 | 权限矩阵验证"能否改设置" | 恢复为 `WP-QA-Lab` |

每轮权限矩阵与接口测试结束后自动执行清场脚本，保证基线数据始终为 **1000 篇文章 / 20000 条评论 / 5 个用户**。
