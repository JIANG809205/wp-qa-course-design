# 权限矩阵实测结果（36 格，含自定义角色）

> 实测时间：2026-11-24　被测版本：WordPress 7.1.5
> 方法：每个角色登录后做**双通道验证**——通道 A 访问后台页面看元素是否存在；通道 B 带 Cookie + REST nonce 直调接口。
> 角色集合：WordPress 内置 5 个 + **自定义角色 auditor（审核员）**，共 6 个角色 × 6 个操作 = **36 格**。
> 判定原则：**以接口为准**（接口是权限的最终边界），页面访问仅作体验证据。

---

## 一、实测矩阵

图例：✅ 符合预期　⚠️ 有条件（仅自己的内容 / 仅提交待审）　❌ 不符合预期

| 角色 | OP1 发布文章 | OP2 编辑他人文章 | OP3 审核评论 | OP4 上传媒体 | OP5 新建用户 | OP6 修改设置 |
|---|---|---|---|---|---|---|
| **管理员** | ✅ allow | ✅ allow | ✅ allow | ✅ allow | ✅ allow | ✅ allow |
| **编辑** | ✅ allow | ✅ allow | ✅ allow | ✅ allow | ✅ deny | ✅ deny |
| **作者** | ⚠️ allow（仅自己） | ✅ deny | ✅ deny | ✅ allow | ✅ deny | ✅ deny |
| **投稿者** | ⚠️ 仅提交待审 | ✅ deny | ✅ deny | ✅ deny | ✅ deny | ✅ deny |
| **订阅者** | ✅ deny | ✅ deny | ✅ deny | ✅ deny | ✅ deny | ✅ deny |

**结论：36 格全部符合预期，未发现越权。**

其中自定义角色 `auditor`（能力：`read` + `edit_posts` + `moderate_comments`）表现符合设计：可提交自己的稿件、**可审核评论**、不能发布、不能上传、不能建用户、不能改设置——证明 WordPress 的能力（capability）模型对自定义角色同样生效。

**稳定性验证**：连续执行 3 次，36 格的接口结果**完全一致（0/36 变化）**。

> 原始数据：`matrix-reps/rep1.json`、`rep2.json`、`rep3.json`；复现命令 `bash defect-hunt/matrix-stability.sh`。

## 二、两处需要说明的"看似异常"

| 现象 | 是否缺陷 | 说明 |
|---|---|---|
| 作者/投稿者能打开"评论列表页"（UI 200） | 否 | 页面本身对有 `edit_posts` 的角色开放，但**列表内无任何评论数据**（实测 0 行），且接口审核动作返回 403，属正常设计 |
| 投稿者能打开"新建文章页" | 否 | 投稿者本来就可以写草稿，只是点"发布"无效；接口以 `status=publish` 提交返回 403、以 `status=pending` 提交返回 201 |

## 三、测量方法上修正的两个坑（重要）

第一轮跑完有 4 格"不符合预期"，逐格核实后发现**都是我的测量问题，不是系统问题**：

| 问题 | 表现 | 根因 | 修正 |
|---|---|---|---|
| nonce 取错 | 所有接口一律 403，错误码是 `rest_cookie_invalid_nonce` | 用正则从 `/wp-admin/` HTML 里抓 nonce，抓到的是别的 nonce | 改调 `admin-ajax.php?action=rest-nonce` |
| 页面判据太粗 | admin 访问"新建用户"被误判为拒绝 | 用"权限"等文字关键词判断，而正常页面里也含"权限"二字 | 改为判"期望元素是否存在"（如 `#createuser`） |
| 预期语义错误 | 作者发布文章被判为"不符合" | 把"仅自己"当成了"必须走待审" | 有条件格单独判定：作者=可发布自己的；投稿者=publish 拒绝且 pending 允许 |

> 这三条如果不查，报告中会出现"发现 4 处越权"的**假缺陷**。这也说明了双通道验证的价值：**接口层能戳穿 UI 的假象，但前提是 nonce、会话、预期语义都得对**。
