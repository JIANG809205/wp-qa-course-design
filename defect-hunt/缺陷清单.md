# 缺陷清单（实测记录）

> 记录时间：2026-11-23　被测版本：WordPress 7.1.5（Docker）
> 说明：每条缺陷均有可复现的请求/操作与真实响应证据，证据文件见 `findings.json`、`findings2.json`。
> 定级标准：P1 严重（安全边界失守/信息泄露可直接利用）、P2 一般（配置缺失或功能异常）、P3 轻微（提示与规范问题）。
> **证据索引**：`evidence/status.csv`（各端点响应码与字节数）、`evidence/headers.txt`（响应头）、
> `evidence/debug-log.png`、`evidence/uploads-index.png`（截图）、`evidence/authors.txt`（作者枚举跳转）。
> **双版本对照**：7.1.4 vs 7.1.5 归一化后各 11/12，结论见 `双版本对照.md`——本清单中的 P1/P2 项属**配置共性问题**，非版本回归。

## DEF-001　登录无失败次数限制（P1）

| 项 | 内容 |
|---|---|
| 所属模块 | 登录与账号 |
| 关联用例 | TC-AUTH-005 |
| 复现步骤 | 1) 打开 `/wp-login.php`；2) 用户名填 `admin`，密码填错误值；3) 连续提交 6 次（密码每次不同） |
| 期望结果 | 达到阈值后出现验证码、临时锁定或返回 429 |
| 实际结果 | 6 次均返回 HTTP 200，始终提示“密码不正确”，无任何限制 |
| 证据 | 连续 5 次响应码 `[200,200,200,200,200]`；第 6 次仍可继续尝试 |
| 风险 | 可被离线字典/在线撞库长期尝试，配合 DEF-005（XML-RPC 开放）放大风险 |
| 建议 | 启用登录限流插件（如 Limit Login Attempts），或 Web 层对 `/wp-login.php` 做频率限制 |
| 状态 | 待修复 |

## DEF-002　调试日志可被匿名下载（P1）

| 项 | 内容 |
|---|---|
| 所属模块 | 系统配置 / 信息泄露 |
| 关联用例 | 探索性测试（本项目开启 `WP_DEBUG_LOG` 后暴露） |
| 复现步骤 | 浏览器或 curl 访问 `http://localhost:8080/wp-content/debug.log` |
| 期望结果 | 403/404，日志不可从 Web 访问 |
| 实际结果 | HTTP 200，返回 4437 字节日志 |
| 证据 | `[23-Nov-2026 12:40:44 UTC] PHP Warning: mysqli_real_connect(): (HY000/2002): Connection refused in /var/www/html/wp-includes/class-wpdb.php on line 1990` |
| 风险 | 泄露服务器绝对路径、框架版本、数据库连接错误细节，为进一步攻击提供信息 |
| 建议 | 生产环境关闭 `WP_DEBUG_LOG`，或将 `debug.log` 移出 Web 根目录；Web 层禁止访问 `*.log` |
| 状态 | 待修复 |

## DEF-003　上传目录开启目录浏览（P2）

| 项 | 内容 |
|---|---|
| 所属模块 | 系统配置 / 信息泄露 |
| 关联用例 | 探索性测试 |
| 复现步骤 | 访问 `http://localhost:8080/wp-content/uploads/` |
| 期望结果 | 403 或 404 |
| 实际结果 | HTTP 200，页面标题 `Index of /wp-content/uploads`，列出目录内容 |
| 证据 | 响应体含 `<h1>Index of /wp-content/uploads</h1>`，共 965 字节 |
| 风险 | 攻击者可枚举全部上传文件（含历史附件、备份文件） |
| 建议 | 在 Apache 配置 `Options -Indexes`，或在 uploads 目录放置 `index.php` |
| 状态 | 待修复 |

## DEF-004　缺少安全响应头（P2）

| 项 | 内容 |
|---|---|
| 所属模块 | 安全配置 |
| 关联用例 | 探索性测试 |
| 复现步骤 | `curl -I http://localhost:8080/` |
| 期望结果 | 至少包含 `X-Frame-Options`、`X-Content-Type-Options`、`Referrer-Policy`、`Permissions-Policy` |
| 实际结果 | 四项全部缺失 |
| 证据 | 响应头仅 `Date`、`Server`、`Content-Type`、`Link` 等 |
| 风险 | 存在点击劫持（缺 X-Frame-Options）、MIME 嗅探（缺 nosniff）等风险 |
| 建议 | Apache 增加 `Header always set X-Frame-Options "SAMEORIGIN"` 等配置 |
| 状态 | 待修复 |

## DEF-005　XML-RPC 接口开放（P2）

| 项 | 内容 |
|---|---|
| 所属模块 | 安全配置 |
| 关联用例 | 探索性测试 |
| 复现步骤 | `POST /xmlrpc.php`，body 为 `system.listMethods` |
| 期望结果 | 关闭该接口（返回 403/404） |
| 实际结果 | HTTP 200，返回 `methodResponse` 与可用方法列表 |
| 证据 | 响应体包含 `<methodResponse>` |
| 风险 | `system.multicall` 可在一个请求内批量尝试大量密码，绕过常规限流 |
| 建议 | Apache 层拦截 `/xmlrpc.php`，或安装禁用 XML-RPC 的插件 |
| 状态 | 待修复 |

## DEF-006　未认证可枚举用户信息（P2）

| 项 | 内容 |
|---|---|
| 所属模块 | REST API |
| 关联用例 | TC-API-006 |
| 复现步骤 | 未登录访问 `/wp-json/wp/v2/users` |
| 期望结果 | 401/403，或仅返回最小字段 |
| 实际结果 | HTTP 200，返回 5 个用户，字段含 `id`、`name`、`slug`、`url`、`description`、`avatar_urls` |
| 证据 | `[{"id":1,"name":"admin","slug":"admin",...}]` |
| 风险 | 泄露管理员登录名，为撞库提供用户名列表 |
| 建议 | 限制该端点仅登录用户可访问，或移除非必要字段 |
| 状态 | 待修复 |

## DEF-007　评论洪水保护对正常用户误伤（观察项，不定级）

| 项 | 内容 |
|---|---|
| 所属模块 | 评论 |
| 关联用例 | TC-COMM-001（补充场景；原用例单条评论通过） |
| 复现步骤 | 在文章页提交第 1 条评论（成功后），间隔数秒再提交第 2 条内容不同的评论 |
| 期望结果 | 第 2 条正常进入待审核 |
| 实际结果 | 返回页面提示“您提交评论的速度太快了，请稍后再发表评论。”，评论未被接收 |
| 证据 | `URL: /wp-comments-post.php`，页面文本包含上述提示 |
| 风险 | 正常用户连续评论被拦截，影响体验；该时间窗口无明确提示 |
| 建议 | 调整洪水保护时间窗，或对已通过审核的用户放宽限制 |
| 定性说明 | 经复核，这是 WordPress 原生 `check_comment_flood` 机制，属**产品设计取舍**而非缺陷；与归因数据集 H-04 的"环境问题"标注保持一致，避免同一现象两种定性 |
| 状态 | 观察项（不计入缺陷数） |

## DEF-008　上传空文件返回 500（P3）

| 项 | 内容 |
|---|---|
| 所属模块 | 媒体库 |
| 关联用例 | TC-MEDIA-005 |
| 复现步骤 | `POST /wp-json/wp/v2/media` 上传 0 字节 png |
| 期望结果 | 4xx 且提示“文件为空” |
| 实际结果 | HTTP 500，`rest_upload_unknown_error`，message 为 "File is empty. Please upload something more substantial." |
| 证据 | 状态码 500 与业务提示语义不匹配 |
| 风险 | 监控会把用户输入错误计为服务端故障，产生噪声 |
| 建议 | 该分支应返回 400 而非 500 |
| 状态 | 待修复 |

## DEF-009　超限上传的错误码与提示不准确（P3）

| 项 | 内容 |
|---|---|
| 所属模块 | 媒体库 |
| 关联用例 | TC-MEDIA-002 |
| 复现步骤 | 上传 20MB 图片（服务端上限 16MB） |
| 期望结果 | 提示“文件超过大小限制”，错误码与语义一致 |
| 实际结果 | HTTP 400，错误码 `rest_upload_no_content_disposition`，提示与“超过大小限制”无关 |
| 证据 | 响应 JSON 中 code 为 `rest_upload_no_content_disposition` |
| 风险 | 用户无法从提示判断真实原因，排障成本高 |
| 建议 | PHP 层超限时返回专用错误码并在前端提示具体上限 |
| 状态 | 待修复 |

| 项 | 内容 |

| 关联用例 | 探索性测试 |

## DEF-011　重复用户名创建返回 500（P3）

| 项 | 内容 |
|---|---|
| 所属模块 | 用户与角色 |
| 关联用例 | 探索性测试（权限矩阵验证时发现） |
| 复现步骤 | 1) 以管理员身份 `POST /wp-json/wp/v2/users` 创建 `dup_probe`；2) 用同一 `username` 再次提交 |
| 期望结果 | HTTP 400，`code=existing_user_login`，提示用户名已存在 |
| 实际结果 | HTTP **500**，响应体却是 `existing_user_login` 业务错误 |
| 证据 | `{"code":"existing_user_login","message":"抱歉，用户名已存在！","data":null}` + 状态码 500 |
| 风险 | 客户端输入错误被记为服务端故障，监控噪声；前端可能显示"服务器错误"而非"用户名已存在" |
| 建议 | 业务校验失败应返回 4xx（此例应为 400/409） |
| 状态 | 待修复 |

## DEF-012　通过 ?author=N 枚举用户名（P2）

| 项 | 内容 |
|---|---|
| 所属模块 | 安全配置 / 信息泄露 |
| 关联用例 | 探索性测试（参照 WPScan 检查清单补充） |
| 复现步骤 | 未登录访问 `/?author=1`、`/?author=2` |
| 期望结果 | 404 或统一跳转，不暴露作者登录名 |
| 实际结果 | 301 跳转到 `http://localhost:8080/author/admin/`、`/author/editor/` |
| 证据 | `author=1 -> 301 /author/admin/`；`author=2 -> 301 /author/editor/` |
| 风险 | 与 DEF-001（登录无限制）组合，可先枚举有效用户名再定向爆破；准确率远高于盲猜 |
| 建议 | 关闭作者归档或将其重写为 ID 形式；或在 Web 层拦截 `?author=` 探测 |
| 状态 | 待修复 |
