从压测数据看，系统吞吐在100线程时达到饱和点91.5 TPS，随后增至200线程反而略降至90.3 TPS，说明已触及处理极限。响应时间随并发增大急剧劣化，100线程时平均响应已达519ms，P95飙升至1549ms；200线程时更恶化至平均1457ms、P95 5272ms，用户体验严重受损。调优Apache workers和InnoDB buffer无效，表明瓶颈可能在后端应用逻辑或数据库查询，而非连接池或缓存命中。mod_cache因响应无缓存头且存在Vary: Cookie标记而完全失效，导致每次请求均动态生成页面。下一步建议：优先修复缓存策略，移除不必要的Vary: Cookie或设置合理缓存头，使mod_cache生效；利用APM工具定位慢SQL或热点代码；考虑引入CDN或静态化首页，从根本上缓解后端压力。
