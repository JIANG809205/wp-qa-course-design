# 大模型评测的方法依据（文献对照）

> 目的：为"样本量、指标、统计报告方式"提供可引用的依据，答辩时被问"你凭什么这么测"可直接回答。

---

## 一、三篇直接可比的工作

### 1. Autonomous QA Agent（arXiv:2601.06034，2025-11）

- **任务**：用 RAG 把 Selenium 脚本生成锚定在真实 DOM 上
- **样本量**：**20 个电商测试场景**
- **报告方式**：`90%（18/20，95% CI：[85%, 95%]，p < 0.001）`，对照组（无 RAG 的普通 LLM 生成）为 **30%**
- **对我们的意义**：
  1. **20 是同类工作的标准样本量**，我们最初的 10 条偏少；
  2. 它把"语法有效"与"执行成功"分开报告——与我们把"严格结构合规"与"可直接运行"分开，是同一套思路；
  3. 它给比例指标配了 **95% 置信区间**，我们应照做（Wilson 区间）。
- 链接：https://arxiv.org/abs/2601.06034

### 2. GenIA-E2ETest（SBES 2025，arXiv:2510.01024）

- **任务**：从自然语言描述生成端到端测试脚本
- **指标**：元素生成**精确率 77%**、元素**召回 77%**、执行**精确率 82%**、执行**召回 85%**、**人工修改率 10%**
- **对我们的意义**：
  1. "元素级指标"（对应我们的**定位器保真度**）是该领域的核心指标，不是我们自创；
  2. "人工修改率"提示我们应报告**人机协作成本**，而不是只报通过率；
  3. 它明确承认"对上下文相关导航与动态内容敏感"——与我们观察到的"约一半定位器虚构"一致。
- 链接：https://arxiv.org/abs/2510.01024

### 3. MacroBench（NeurIPS 2025 Workshop，arXiv:2510.04363）

- **任务**：Web 自动化脚本合成基准
- **规模**：7 个自托管站点、**681 个任务、2636 次模型-任务运行**
- **验证协议**：静态检查 → 沙箱执行 → 结果验证（DOM 断言 + 数据库快照）
- **对我们的意义**：
  1. 它证明"只做静态检查不够，必须真跑"，与我们"编译 + 可运行性 + 定位器保真"三重校验一致；
  2. 它报告的"简单任务 91.7% 成功、复杂工作流 0.0%"与我们"状态迁移类 0/10"的观察相互印证；
  3. 它给出的分层结论提醒我们：**不要把不同难度的用例混在一起报一个平均值**。
- 链接：https://arxiv.org/abs/2510.04363

## 二、据此确定的本项目方案

| 维度 | 文献做法 | 本项目调整 |
|---|---|---|
| 脚本样本量 | 20（arXiv 2601.06034） | **10 → 20**，补齐登录/内容/媒体/评论/接口/权限六类 |
| 用例样本量 | 按功能点分组生成 | 20 功能点 × 约 10 条 = 每轮 196–198 条 |
| 归因样本量 | 无直接可比（多为端到端） | 24 条平衡样本（8/8/8），难度分层 |
| 比例指标报告 | 比例 + 95% CI | **全部比例指标补 Wilson 95% 置信区间** |
| 指标分层 | 元素级 / 执行级分开 | 严格结构合规 / 定位器保真 / 可直接运行 三层分开 |
| 验证手段 | 静态 + 执行 + 结果 | 编译（javac）+ 定位器比对 + 可运行性判定 |
| 重复实验 | 3 次报均值±标准差 | 主力模型 3 轮；另两模型单轮并显式声明 |

## 三、Wilson 置信区间说明（写进报告）

样本量小的时候，用 `p ± 1.96·√(p(1-p)/n)` 会在 p 接近 0 或 1 时越界（出现负值或大于 1）。因此采用 **Wilson 区间**：

$$\frac{\hat p + \frac{z^2}{2n} \pm z\sqrt{\frac{\hat p(1-\hat p)}{n} + \frac{z^2}{4n^2}}}{1 + \frac{z^2}{n}}$$

例：10 条脚本中 6 条可运行，点估计 60%，Wilson 95% CI 约为 **[31%, 83%]**——区间很宽，说明 10 条样本不足以给出精确结论；扩到 20 条后区间会明显收窄，这正是扩样的理由。

## 四、报告中的引用写法

> 本文的评测指标设计参考了近期 LLM 测试生成方向的实证工作：脚本级评估采用 20 个场景的规模并报告 95% 置信区间（Vali, 2025）；元素级指标与执行级指标分离报告的做法沿用 GenIA-E2ETest（Júnior et al., SBES 2025）；静态检查与真实执行相结合的验证协议参考 MacroBench（Kim & Kim, NeurIPS 2025 Workshop）。

## 六、定位器保真度的基准集（本项目的关键修正）

文献中的"元素精确率"通常以**真实页面元素集**为基准。本项目最初用**手写的 22 个 id** 作基准，导致保真度被高估（30%–57%）。改为用 Selenium 登录后逐页抓取 **9 个后台页面**的完整属性集：

| 基准 | 数量 |
|---|---|
| 元素 id | 1181 |
| 表单 name | 193 |
| CSS class | 769 |

据此重算后，三模型（20 条脚本）定位器保真度为 **21.1% / 24.4% / 25.0%**，即**四分之三以上定位器在真实页面上不存在**。这与文献中"标准 LLM 元素解析率约 40%"的观察方向一致（本项目更低，因为脚本未提供 DOM 上下文）。

脚本：`collect_dom_ids.py`（抓基准）、`selector_fidelity_dom.py`（比对）。
