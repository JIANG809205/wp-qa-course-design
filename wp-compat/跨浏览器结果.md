# 跨浏览器兼容性测试结果

> 测试时间：2026-11-24
> 目的：验证被测系统在不同浏览器渲染引擎下是否都能正常布局与操作
> 结论：**Chrome 12/12、Firefox 12/12，合计 24/24 全部通过**

---

## 一、测试矩阵

| 维度 | 取值 |
|---|---|
| 浏览器 | Chrome 158.0.8127.36（WSL headless）、Firefox 155.0.1（Windows 本机 headless） |
| 视口 | 1920×1080、1366×768、375×812 |
| 页面 | 首页 `/`、博客列表 `/qa-blog/`、登录页 `/wp-login.php`、后台文章列表 `/wp-admin/edit.php` |
| 判据 | ① `documentElement.scrollWidth - clientWidth ≤ 4px`；② 不存在宽度超过视口的元素 |
| 合计 | 2 浏览器 × 3 视口 × 4 页面 = **24 组** |

---

## 二、结果

| 浏览器 | 1920 | 1366 | 375 | 合计 |
|---|---|---|---|---|
| Chrome | 4/4 | 4/4 | 4/4 | **12/12** |
| Firefox | 4/4 | 4/4 | 4/4 | **12/12** |
| **总计** | 8/8 | 8/8 | 8/8 | **24/24** |

**全部 24 组的横向溢出均为 0px，超宽元素数量均为 0。**

---

## 三、关键观察

1. **375px 下后台自动切换移动布局**：两种浏览器中，WordPress 后台都折叠为顶部汉堡菜单，文章列表改为卡片式，未出现横向滚动。这是 WordPress 自带的响应式管理界面行为，不是主题适配的结果。
2. **两种浏览器渲染一致**：同一页面的溢出表现完全相同（都为 0），说明 Twenty Twenty-Five 主题与后台样式没有使用引擎相关的特殊写法。
3. **截图存证**：Chrome 12 张在 `wp-compat/screenshots/`，Firefox 12 张在 `wp-compat/firefox/`。

---

## 四、技术实现说明

| 项 | Chrome 侧 | Firefox 侧 |
|---|---|---|
| 运行位置 | WSL2 Ubuntu 22.04 | Windows 本机 |
| 驱动 | Selenium Manager 自动匹配 | geckodriver 0.36.0（npmmirror 镜像下载） |
| 浏览器 | Chrome 158（apt 安装） | Firefox 155（用户已装） |
| 会话管理 | 单会话复用到 3 视口 | **每视口新建会话**（复用会因窗口调整崩溃，已修正） |

> 期间踩过的坑：Firefox 复用同一个 `Service` 对象连续切换视口时，driver 进程会以 `status 0` 退出；改为"每视口新建 `Options` + `Service`"后 12/12 稳定通过。

---

## 五、局限

| 局限 | 说明 |
|---|---|
| 未覆盖 Safari | Windows/Linux 环境无法运行 Safari；其 WebKit 引擎行为可能与 Chromium/Gecko 不同 |
| 未覆盖 Edge | 与 Chrome 同为 Chromium 内核，预期一致，但未实测 |
| 未测移动真机 | 375px 仅为视口模拟，未在真实 iOS/Android 设备验证触摸与滚动 |
| 未测旧版本浏览器 | 只测最新稳定版，未覆盖旧版兼容性 |
